# 📚 Homework Bot

Telegram-бот для школьника и класса: присылаешь домашку как угодно — текстом,
фото дневника или доски, альбомом, пересланным из чата — бот находит все
задания, ставит даты сдачи по расписанию и записывает. Вечером напоминает,
что на завтра. К боту прилагается Telegram Mini App на Next.js.

---

## Что бот умеет

**Личный чат**
- **Прислал — записано.** Текст, фото, картинка файлом, альбом до 10 фото,
  подпись к фото, пересланное сообщение — всё разбирается одним запросом.
  Из одного сообщения достаются все задания по всем предметам
- Дата сдачи: явная из сообщения («к пятнице», «на 30.10»), иначе — ближайший
  урок предмета по расписанию. Относительные даты в пересланном считаются
  от дня, когда его написали. Даты модели проверяются кодом: прошедшие
  и невозможные отбрасываются
- Бумажный дневник читается правильно: задание в строке дня — это день сдачи
- Названия предметов приводятся к расписанию («англ. яз.» → «Английский язык»)
- Карточка с результатом: поправить дату, удалить лишнее, отменить всё одной
  кнопкой. Сомнительные распознавания помечены «проверь»
- Список заданий `/hw` (кнопка «📋 Мои ДЗ»): личные и задания класса, по датам,
  с отметкой «сделано»
- Вечерние напоминания о невыполненном ДЗ (`/reminders`) — включаются одной
  кнопкой прямо из карточки
- Расписание по фото (`/setup`) или в редакторе по дням (`/schedule`)
- График нагрузки класса на 2 недели

**Группа / канал класса**
- Настройка класса одним фото расписания (`/setup`) — предметы и уроки
  распознаются моделью, вручную заполнять ничего не нужно
- Пассивный мониторинг: бот читает сообщения и фото, сам находит ДЗ.
  Переписка отсеивается локальным фильтром — в LLM уходит лишь малая часть
  сообщений, что экономит вызовы модели
- Найденное ДЗ записывается сразу с датой из расписания — реакция 👀 и
  карточка, где дату можно поправить. Карточка сама удаляется через 10 минут
- Замены и отмены уроков распознаются прямо из сообщений чата,
  последнюю можно откатить (`/undo_change`)
- Подгруппы (`/my_group`) и чередование числитель/знаменатель (`/set_week`):
  каждый ученик видит только свои уроки
- Список ДЗ `/hw` с кнопками удаления (приходит в личку, чтобы не засорять чат),
  быстрые сводки `/today` и `/tomorrow`
- Защита от дублей, права на удаление — только у администраторов
- Экспорт агрегированных метрик нагрузки в CSV

**Mini App (Next.js)**
- Список ДЗ с личными отметками о выполнении
- Добавление и редактирование заданий, включая фото
- Расписание по дням, трекер оценок с целевыми баллами
- Визуализация учебной нагрузки

## Стек

| Компонент | Технология |
|---|---|
| Бот | `aiogram 3.x` (long polling) |
| Разбор ДЗ | GigaChat 2 (Сбер): `Max` — личные ДЗ, `Lite` — текст чата, `Pro` — фото чата |
| Запасная модель | Mistral `ministral-14b-latest` — если GigaChat не ответил |
| Ответ модели | JSON по схеме (structured output), даты и предметы проверяются кодом |
| Календарь | Google Calendar API (необязательно, из меню убран) |
| БД | SQLite (stdlib `sqlite3`) |
| HTTP / REST | `aiohttp` |
| Графики | `matplotlib` |
| Mini App | Next.js 14 (App Router), Tailwind, framer-motion |

## Запуск локально

```bash
pip install -r requirements-dev.txt
cp .env.example .env      # заполни BOT_TOKEN и GIGACHAT_CREDENTIALS
python main.py
```

Бот стартует long polling и поднимает HTTP-сервер на `$PORT` (по умолчанию 8080):
`/` — health-check, `/api/*` — REST для Mini App.

### GigaChat

1. [developers.sber.ru/studio](https://developers.sber.ru/studio) → создать
   проект **GigaChat API** (тариф Freemium для физлиц, без карты)
2. Настройки API → **Получить ключ** → скопировать «Ключ авторизации»
3. Вписать в `GIGACHAT_CREDENTIALS`

TLS-сертификат GigaChat выдан российским удостоверяющим центром. Его корень
лежит в `certs/russian_trusted_root_ca.pem` и подключается автоматически —
отключать проверку сертификата не нужно.

Mistral (`MISTRAL_API_KEY`) — запасной: подхватывает, если GigaChat не ответил.

### Google Calendar (необязательно)

Из меню убран: задания хранятся в боте и Mini App. Команды `/auth` и
`/disconnect_calendar` продолжают работать для тех, кто уже подключал.

`credentials.json` — один на всё приложение, настраивается администратором:

1. [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Library → **Google Calendar API** → Enable
2. Credentials → Create Credentials → **OAuth 2.0 Client ID** → Desktop app
3. Скачай JSON → переименуй в `credentials.json` → положи в `data/`

На хостинге без постоянного диска содержимое файла можно передать
переменной `GOOGLE_CREDENTIALS_JSON`.

Дальше **каждый ученик подключает свой календарь сам**: `/auth` → перейти по
ссылке → отправить боту код. Токен сохраняется в таблице
`user_calendar_tokens` и привязан к его `user_id`, поэтому ДЗ попадает
именно в его календарь. Отвязать — `/disconnect_calendar`.

> **Обновление со старой версии.** Раньше токен был один на весь бот
> (`data/token.json`), и события всех пользователей уходили в календарь того,
> кто авторизовался первым. При первом запуске новой версии этот файл
> автоматически переносится в БД как токен `ADMIN_USER_ID`, после чего
> удаляется. Остальным пользователям нужно выполнить `/auth`.

## Деплой

Основной хостинг — Amvera (российские IP: GigaChat доступен, а зарубежные
модели вроде Claude, GPT и Gemini — нет). Переменные окружения задаются в
настройках проекта Amvera; после обновления добавь туда `GIGACHAT_CREDENTIALS`.

В репозитории также лежат конфиги для двух других платформ:

- `render.yaml` — Render: worker для бота + web-сервис для Mini App, диск на `/data`
- `railway.json` + `Procfile` — Railway

Обязательные переменные окружения: `BOT_TOKEN` и хотя бы один ключ модели —
`GIGACHAT_CREDENTIALS` или `MISTRAL_API_KEY`. Их отсутствие останавливает запуск с явным сообщением; необязательные, но
влияющие на поведение — логируются предупреждением. Полный список с
комментариями — в `.env.example`.

**Точка входа — `main.py`.** Если start command задан вручную в дашборде
хостинга, он перекрывает файл конфигурации: проверь, что там
`python main.py`, а не `python bot.py`.

**Бот и Mini App деплоятся вместе.** Бэкенд требует подписи `initData`,
которую старые сборки фронта не отправляли: при рассинхроне приложение
получит 401 с сообщением «Приложение устарело», а в логе бота появится
предупреждение о вероятной пересборке.

**Сохранность данных.** SQLite лежит в `DATA_DIR` (по умолчанию `/data`, если
такой каталог существует). Без постоянного диска база теряется при редеплое,
поэтому расписание и предметы дублируются в переменную `SCHEDULE_BACKUP` и
восстанавливаются автоматически при старте с пустой БД.

**Несколько классов.** Один бот обслуживает произвольное число классов.
Класс пользователя определяется по данным бота: он писал в чат, владеет его
расписанием (`/link_schedule`) или отмечал там задания выполненными.
Расписание, список ДЗ и график нагрузки выдаются только по его чатам.

`WEBAPP_CHAT_ID` остаётся как явное указание для установки на один класс —
тогда задания из Mini App привязываются к этой группе. Если переменная не
задана, привязка определяется автоматически.

## Приватность

Модуль аналитики хранит только агрегированные данные на уровне чата:
количество заданий, суммарное время, индекс нагрузки. `user_id`, имена учеников
и тексты переписки в таблицы аналитики не попадают, в CSV-экспорт — тоже.
В LLM для оценки времени уходит только предмет и текст задания. Для разбора
ДЗ модели передаются текст и фото присланного сообщения и список предметов
из расписания; загруженные в GigaChat фото удаляются сразу после ответа.

Методология расчёта — `docs/ANALYTICS.md`.
